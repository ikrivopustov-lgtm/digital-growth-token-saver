# Codex Token Saver

Цель: тратить меньше токенов **на обвязку и шум**, а не на мышление там, где оно нужно.
Явные инструкции пользователя всегда важнее этого скилла.

Постоянные правила живут в блоке `codex-token-saver` в AGENTS.md (читается каждый ход).
Этот файл — процедуры, которые нужны по запросу. Не пересказывай его пользователю.

## Команды

Рантайм установлен в `~/.codex/token-saver/`. Все команды — из корня проекта.

| Задача | Команда |
|---|---|
| Установить в проект | `bash ~/.codex/token-saver/install.sh --project .` |
| Проверить состояние | `~/.codex/token-saver/tsctl status --project .` |
| Делегировать рутину | `bash ~/.codex/token-saver/delegate.sh [-w] "<задача>"` |
| Расход по сессии с субагентами | `python3 ~/.codex/token-saver/vendor/codex-astra-luna-orchestrator/scripts/token_usage.py --latest` |

Если `~/.codex/token-saver/` нет — скилл не установлен: скажи пользователю запустить
`bash <путь-к-скиллу>/scripts/install.sh --project .` и остановись.

## 1. Триаж задачи (в первом ответе, одной строкой)

Определи класс и напиши одну строку вида `Класс: рутина · профиль: fast · план: нет`.

| Класс | Признаки | Процесс | Профиль |
|---|---|---|---|
| tiny | 1 файл, понятно что менять, <20 строк | сразу делать | текущий |
| routine | переименование, формат, тексты, тесты по образцу, bump, мелкий фикс | сразу делать, узкие проверки | `fast` |
| feature | 2+ файла, новая логика, понятные требования | `$aif-plan fast` → `$aif-implement` | план на текущем, реализация `impl` |
| deep | архитектура, миграции/схемы, auth/платежи/безопасность, гонки, непонятный баг, 10+ файлов | `$aif-explore` при неясности → `$aif-plan full` (или `ultra`) на `deep` → новая сессия `codex -p impl` → `$aif-implement` | `deep` для плана |

Модель не может сама сменить профиль. Если текущий профиль не совпадает с классом —
скажи это одной строкой с готовой командой (`/model …` или `codex -p fast`) и продолжай,
не жди ответа, если только класс не `deep` на дешёвой модели с `low` effort — тогда
сначала спроси.

Хук `context_guard` сам подсвечивает явные несоответствия (дорогая модель на рутине,
дешёвая на сложном). Сообщения хука — сигнал, а не приказ: если видишь, что задача
на самом деле другого класса, опиши это пользователю.

## 2. Plan-first через ai-factory

- План — это артефакт в `.ai-factory/` (`PLAN.md` для fast, `plans/<id>.md` для full,
  `plans/<id>/index.md` + фазы для ultra). Он же — память между сессиями вместо длинной истории.
- `fast` — по умолчанию для feature. `full` — когда нужны ветка, тесты/доки в плане.
- `ultra` — только для deep: он специально рассчитан на «план сильной моделью, реализация слабой».
- `$aif-improve` и цикл plan-coordinator — только если план явно сырой: каждый проход стоит токенов.
- tiny и routine **не планируются** — план дороже самой правки.
- Между планом и реализацией сделай паузу: план показать, получить «ок».

## 3. Контекст и /compact

Слэш-команды запускает только пользователь. Твоя задача — вовремя предложить.

- Хук показывает пользователю процент контекста на порогах 60/75/85%.
- Получив сигнал ≥75%: доведи текущий шаг до стабильной точки, отметь прогресс
  в плане `.ai-factory`, и в конце ответа одной строкой предложи `/compact`
  (или новую сессию: `codex -p impl` → `$aif-implement` — план продолжит с того же места).
- Без хука: предлагай `/compact` после каждой завершённой фазы плана и перед сменой темы.
- Не предлагай компакт посреди отладки с живым стеком ошибок — сначала зафиксируй
  находки в плане или `.ai-factory/RESEARCH.md`.

## 4. Делегирование

Подробно: `references/delegation.md`. Правила:

- По умолчанию работаешь сам. Субагенты удваивают контекст: каждый перечитывает своё.
- Делегируй только: (а) чтение/поиск по большому объёму кода, результат которого нужен
  коротким отчётом; (б) 2+ действительно независимых куска с разными файлами;
  (в) независимое ревью рискованного диффа.
- Роли (`explorer`, `worker`, `tester`, `reviewer`, `researcher`) лежат в `.codex/agents/`
  с закреплёнными моделями. `$astra-orchestrator` — только когда пользователь его вызвал.
- Для рутины вне текущего контекста: `delegate.sh` запускает отдельный `codex exec`
  на профиле `fast` и проверяет, какая модель реально ответила.
- После сессии с субагентами проверь модели через `token_usage.py --latest`:
  в Codex App есть баг, когда субагенты молча наследуют дорогую модель родителя.

## 5. Что нельзя срезать (качество)

Полный список: `references/quality-guardrails.md`. Коротко:

- Не понижай effort и не делегируй дешёвой модели: безопасность, auth, платежи,
  миграции данных, конкурентность, удаление данных, публичные API.
- Фильтруя вывод, никогда не прячь ошибку: при падении команды покажи блок ошибки целиком.
- Тесты затронутого кода запускаются всегда. Полный прогон — перед коммитом/PR.
- Две неудачные попытки на дешёвой модели или `low` effort → остановись и предложи `deep`.
- Экономия никогда не оправдывает догадку вместо чтения нужного файла.

## Установка и проверка (когда пользователь просит)

1. `bash ~/.codex/token-saver/install.sh --project . --dry-run` — покажи план изменений.
2. После «ок» — без `--dry-run`. Установщик делает бэкапы и ничего не перезаписывает без `--force`.
3. `~/.codex/token-saver/tsctl status --project .` — покажи итог.
4. Напомни: проект должен быть trusted, иначе Codex не читает `.codex/config.toml`
   и `.codex/hooks.json`. Проверка — `/status` в новой сессии.
