## Token discipline (codex-token-saver)

Правила пользователя важнее этого блока. Процедуры — в скилле `$codex-token-saver`.

### Процесс
- Первой строкой ответа: `Класс: tiny|routine|feature|deep · профиль · план: да/нет`.
- tiny/routine — делать сразу, без плана. feature — `$aif-plan fast` → подтверждение → `$aif-implement`.
  deep — `$aif-plan full|ultra` на профиле `deep`, реализация в новой сессии `codex -p impl`.
- Профиль не совпадает с классом → одна строка с командой (`/model …`, `codex -p fast|impl|deep`).
- Прогресс хранится в плане `.ai-factory/`, а не в истории чата.

### Чтение и вывод
- Сначала `rg`/поиск символа, потом нужный диапазон строк. Не перечитывать неизменённые файлы.
- Не заходить в: node_modules/, dist/, build/, .next/, vendor/, coverage/, *.lock, *.min.*, логи, дампы данных.
- Успешные команды — с узким выводом (`--stat`, `-q`, `| tail -n 60`). Упавшие — блок ошибки целиком.
- Тесты затронутого кода — всегда; полный прогон — перед коммитом/PR/деплоем.

### Контекст
- Сигнал хука ≥75% или завершена фаза плана → зафиксировать прогресс в плане и предложить `/compact`
  (или новую сессию с `$aif-implement`).

### Субагенты
- По умолчанию работать самому. Делегировать: объёмное read-only исследование, 2+ независимых
  куска с разными файлами, ревью рискованного диффа. Роли: explorer, worker, tester, reviewer, researcher.
- `$astra-orchestrator` — только по явной просьбе пользователя.
- Один писатель на файл. Контракт: цель · файлы · ограничения · результат · критерий приёмки.

### Не экономить на
- безопасности, auth, платежах, миграциях, конкурентности, удалении данных, публичных API —
  там сильная модель и нормальный effort. 2 неудачи на дешёвой модели → предложить `deep`.

### Ответы
- Коротко: что изменено, чем проверено, что осталось. Без пересказа процесса.
