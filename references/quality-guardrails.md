# Ограничители качества

Экономия токенов не должна превращаться в экономию на правильности.
Эти правила перекрывают любые другие правила скилла.

## Всегда на сильной модели и нормальном effort

- безопасность, auth, права доступа, секреты;
- платежи, биллинг, деньги;
- миграции данных, изменение схем, удаление данных;
- конкурентность, гонки, очереди, ретраи;
- публичные API и контракты между сервисами;
- баг, причина которого непонятна после первой попытки.

## Вывод команд

- Узкий вывод (`--stat`, `-q`, `| tail -n 60`) — только пока команда проходит.
- Если команда упала — покажи блок ошибки целиком (`grep -n -A30 -E "FAIL|Error|Traceback"`
  или перезапуск без фильтра). Обрезанный stacktrace = сломанная диагностика.
- Не понижай `tool_output_token_limit` и `model_auto_compact_token_limit` ради экономии:
  первое прячет ошибки, второе чаще сжимает историю и теряет детали.

## Проверки

- Тесты затронутого кода — всегда.
- Полный прогон, линтер и сборка — перед коммитом, PR и деплоем.
- Не отмечай задачу в плане выполненной без проверки.

## Эскалация

- 2 неудачные попытки на `fast` / `low` → стоп, предложить `deep`.
- Субагент вернул неуверенный или противоречивый результат → корень перепроверяет сам.
- «Не нашёл других вызовов» от дешёвой модели — перепроверь `rg` перед изменением API.

## Чтение

- Сначала `rg`/символьный поиск, потом диапазон строк — но нужный файл читается,
  даже если он большой. Догадка вместо чтения запрещена.
